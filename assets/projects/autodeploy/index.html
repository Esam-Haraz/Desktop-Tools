01 DUAL-PHASE ARCHITECTURE

1. Silent Setup vs. 2. Custom Setup

AutoDeploy divides your software deployment into two sequential phases stored in portable .txt files alongside the executable, giving you 100% unattended speed where you want it and manual control where you need it.

[PHASE 1 // UNATTENDED] AutoDeploy Silent Queue.txt

1. Silent Setup

Runs 100% silently in the background with zero pop-ups, wizard windows, or manual 'Next' clicks.

  • Inspects binary signatures for Inno Setup, NSIS, WiX Burn, Squirrel, Omaha, InstallShield, and 7z SFX.
  • Extracts case-sensitive switches directly from embedded help tables (e.g., FastCopy, Java, DirectX).
  • Automatically quotes paths and bypasses 'pause' commands in .bat and .cmd scripts.
  • Restores missing Desktop shortcuts from Start Menu after silent installation.
[PHASE 2 // INTERACTIVE] AutoDeploy Custom Queue.txt

2. Custom Setup

Launches the normal interactive installer UI for programs where you want manual control over paths and components.

  • Ideal for heavy IDEs, compilers, or tools where you change the target drive (e.g., D:\) or pick custom checkboxes (Git, Python, VS Code).
  • Pauses the queue patiently until you finish and close the installer window.
  • Immediately executes any configured Post-Install Additional Steps once the setup window closes.
  • Smart Queue Move: Dragging an item from Silent to Custom preserves all of its configured Additional Steps.

03 BATTLE-TESTED ON BARE-METAL WINDOWS

8 Real-World OS Challenges & Engineered Solutions

Fresh Windows installations lack root certificates, C++ runtimes, and registry states. Here is how AutoDeploy diagnoses and solves the 8 toughest post-format problems:

#01 — Drag & Drop Blocked into Elevated Window

[WIN32 UIPI ISOLATION]
FAULT // OS STATE

Windows User Interface Privilege Isolation (UIPI) blocks dragging files from Explorer (standard user) into an elevated Administrator window.

PATCH // AUTODEPLOY SOLUTION

AutoDeploy launches as a standard user so Drag & Drop works natively, requesting a single on-demand UAC elevation (--autorun-install) only when starting deployment.

#02 — SSL: CERTIFICATE_VERIFY_FAILED on Fresh OS

[MISSING ROOT CERTS]
FAULT // OS STATE

A freshly formatted Windows OS has not yet fetched Root Certificates from Windows Update, causing strict HTTPS handshakes to fail.

PATCH // AUTODEPLOY SOLUTION

Performs one upfront connectivity check (skipping all checks if offline) and uses a Smart SSL Fallback that retries failed handshakes with an unverified SSL context.

#03 — False-Positive [SKIPPED] Detections

[REGISTRY MATCHING]
FAULT // OS STATE

Scanning Program Files folder names matches generic vendor folders (Microsoft, Windows), and naive regex truncates 'Uninstaller' into 'Pro'.

PATCH // AUTODEPLOY SOLUTION

Enforces strict word boundaries (\b) during metadata cleaning and matches normalized software names exclusively against Windows Uninstall Registry keys.

#04 — Batch Files (.bat) Failing with Code 1 or Hanging

[BATCH RUNNER]
FAULT // OS STATE

Folder paths with spaces (e.g., D:\Windows Programs) break unquoted %~dp0 calls inside batch scripts, and 'pause' halts unattended execution.

PATCH // AUTODEPLOY SOLUTION

Dynamically generates a runner script that prepends @cd /d "%~dp0", wraps unquoted %~dp0 calls in quotes, strips pause, and redirects stdin to DEVNULL.

#05 — Installers Rejecting '/S' (Java & FastCopy)

[BINARY INSPECTION]
FAULT // OS STATE

Custom installers enforce case-sensitive flags ('/s' in Java or '/SILENT' in FastCopy) or store engine signatures in UTF-16LE instead of ASCII.

PATCH // AUTODEPLOY SOLUTION

Combines dual-encoding binary scanning, internal help-string mining, and a Smart Retry timer that tests fallback switches if an installer exits in < 4.5s.

#06 — Missing Desktop Shortcuts After Silent Setup

[SHORTCUT SYNC]
FAULT // OS STATE

Most silent installers disable desktop shortcut creation by default unless explicitly instructed.

PATCH // AUTODEPLOY SOLUTION

Passes /MERGETASKS="desktopicon" for Inno Setup and diffs Start Menu\Programs before and after installation to copy new .lnk shortcuts to the Desktop.

#07 — Hidden System Folders (ProgramData) Turning Visible

[ATTRIBUTE GUARD]
FAULT // OS STATE

Creating directories or copying license/config files into system paths can strip parent folder attributes.

PATCH // AUTODEPLOY SOLUTION

Attribute Guard snapshots parent directory flags via Win32 GetFileAttributesW before copying and restores Hidden & System flags via SetFileAttributesW.

#08 — App Failing to Open on Bare-Metal Windows

[EMBEDDED VC++ RUNTIME]
FAULT // OS STATE

PyQt6 requires Visual C++ runtime DLLs (msvcp140.dll, vcruntime140.dll) that do not exist on a fresh Windows install before drivers are installed.

PATCH // AUTODEPLOY SOLUTION

Bundles the required Visual C++ DLLs directly inside the standalone AutoDeploy.exe binary during PyInstaller compilation so it runs from second one.

[CHANGELOG 01 // UNATTENDED FLOW] v1.2.0

Unattended Deployment & Update Handling

  • ✓ Smart Unattended Timeout

    If an update prompt times out without user input during Silent Setup, AutoDeploy now assumes the session is unattended, keeps the local version, and automatically skips update checks for the remaining items in that phase instead of waiting 60 seconds per app.

  • ✓ Automatic Reset for Custom Setup

    Update prompts are automatically re-enabled when Phase 2 (Custom Setup) begins so interactive installations always check for updates normally.

[CHANGELOG 02 // STABILITY & MUTEX] v1.2.0

Stability, Window Closing & Concurrency

  • ✓ Safe Stop & Close Flow

    Fixed a race condition between QThread.finished and isRunning() when stopping a deployment or closing the window mid-run. Clicking Close (✕ / Alt+F4) while stopping now waits cleanly for the active step to finish before exiting.

  • ✓ Readable Close Confirmation Dialog

    Applied a high-contrast dark theme to the "Deployment in Progress" confirmation prompt so text and buttons are clearly visible.

  • ✓ 64-Bit Safe Single-Instance Mutex

    Updated CreateMutexW / CloseHandle bindings with explicit 64-bit ctypes signatures (use_last_error=True), proper ERROR_ACCESS_DENIED handling for elevated instances, and fail-open behavior on unexpected OS mutex errors.

  • ✓ Crash Dialog Rate-Limiting

    All unhandled exceptions continue to be written to crash_log.txt, while modal error popups are now limited to at most once every 30 seconds to prevent dialog stacking.

[CHANGELOG 03 // BATCH & LOGS] v1.2.0

Batch Runner & Logging Improvements

  • ✓ Arabic / UTF-8 Batch Path Fix

    Added re.ASCII flags to regex substitutions in the .bat / .cmd runner so UTF-8 multibyte characters (such as Arabic filenames) are never misinterpreted as whitespace during automatic %~dp0 path quoting or pause bypassing.

  • ✓ Cleaner Logs

    Removed duplicate exit code 1638 ("already installed") log messages and ensured the storage path note is always included in exported log files without duplicating it in the UI console.
